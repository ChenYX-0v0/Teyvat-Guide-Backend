## 1. 项目概况

「AI 提瓦特向导」（teyvatGuide）是一个面向 C 端用户的《原神》智能助手工具站：

| 项 | 说明 |
| --- | --- |
| 技术栈 | Go Gin + React SPA + GORM + MySQL（独立库 `teyvat_guide`） |
| 鉴权 | C 端 JWT；管理接口用 `X-Admin-Key` 静态密钥 |
| 已有管理 API | `POST /api/admin/assets/import`、`GET /api/admin/assets/missing`、`POST /api/admin/assets/reload` |
| 健康检查 | `GET /api/health`，返回 `{ status, version, time }` |
| 部署形态 | 独立 Go 进程，默认 `http://localhost:8080` |

## 2. 接入方式（混合模式）

采用「**数据直连 + 生效通知走网关**」的混合模式：

```
映射数据维护：本系统 ──TypeORM 直连──► MySQL(teyvat_guide 库) 的 asset_* 映射表
生效通知：    本系统 ──网关代理──► http://127.0.0.1:8080/api/admin/assets/reload
服务状态：    本系统 ──网关代理──► http://127.0.0.1:8080/api/health
```

- 两个数据库都在同一 MySQL 实例（`demo_project` / `teyvat_guide`），直连成本低。
- 注册表配置：`code = "teyvat-guide"`，`auth_type = "header-key"`，`auth_config` 存 X-Admin-Key（当前取该项目 `config.yaml` 的 `auth.jwt_secret`）。
- 本系统浏览器侧只携带自身 Session，X-Admin-Key 与数据库连接信息不出服务端。
- 该项目无需配置 CORS。

## 3. 功能模块设计

### 3.1 资产映射管理（M2 · 直连 teyvat_guide 库）

**连接层：**

```
src/lib/teyvat/
├─ db.ts          # 第二个 TypeORM DataSource（teyvat_guide 库），synchronize: false
├─ entities/      # 影子实体：与 Go GORM 模型字段一一对应
│  ├─ TeyvatCharacter.ts   # asset_characters
│  ├─ TeyvatWeapon.ts      # asset_weapons
│  └─ TeyvatRelicSet.ts    # asset_relic_sets
└─ assets.ts      # 业务封装：list / upsert / remove / reloadMemory
```

- 影子实体标注「外部 Schema，归 teyvatGuide AutoMigrate 所有」，**本系统禁止对它做任何迁移**，只读写。
- 独立 env：`TEYVAT_DB_NAME` 等（复用同一 host/账号）。

**功能模块：**

| 模块 | 表 | 操作 |
| --- | --- | --- |
| 角色管理 | `asset_characters` | 列表（分页/搜索）、新增（avatarId + 名称/元素/星级/图标）、编辑、删除 |
| 武器管理 | `asset_weapons` | 同上（weaponId / type / rarity） |
| 圣遗物套装管理 | `asset_relic_sets` | 同上（setId / name / icon） |

UI：菜单「AI 提瓦特向导」下新增「资产映射管理」，页内 Tabs 切换三张表；TDesign Table + Dialog 编辑；rarity 用星级 Tag，element 用彩色 Tag。

**缓存同步（关键）：**

teyvatGuide 启动时把映射表全量加载进内存，直改数据库它感知不到，因此每次写操作后：

```
本后台写库成功
  → ① POST /api/gateway/teyvat-guide/api/admin/assets/reload（走网关，刷新 Go 内存）
  → ② SQL 清空 asset_player_profile_snapshots（旧快照不含新翻译）
  → 页面提示「已保存并生效」
```

reload 失败不回滚写库（数据已正确，只是内存暂时旧），页面明确提示「已入库，内存刷新失败，请检查 teyvatGuide 是否在线」。

### 3.2 翻译缺漏补录（M2-3 · 直连）

| 模块 | 说明 |
| --- | --- |
| 缺漏清单 | 直连查 `asset_missings`（kind / asset_id / hit_count / first_seen），按命中数倒序 |
| 一键补录 | 从缺漏行直接打开对应映射表的编辑框，保存后走统一缓存同步流程 |

### 3.3 业务侧管理接口（远期 · 需 teyvatGuide 补接口）

| 模块 | 需新增接口 | 用途 |
| --- | --- | --- |
| 用户管理 | `/api/admin/users`（列表/封禁） | 查看 C 端用户、封禁账号 |
| 对话数据查看 | `/api/admin/chats`（会话/消息查询） | 审计对话内容、统计 Token 用量 |
| UID 绑定管理 | `/api/admin/bindings`（查询/解绑） | 管理用户 ↔ 游戏 UID 绑定关系 |
| 运行概览 | `/api/admin/stats` | 今日问答量、Token 消耗、快照缓存命中率 |

以上接口由 teyvatGuide 侧按其「新增接口五步法」分层规范实现，本系统通过网关代理对接。

## 4. teyvatGuide 侧需要的配合

1. **鉴权升级（建议）**：管理接口当前复用 `auth.jwt_secret` 作为 X-Admin-Key，建议升级为独立的 admin token，与 JWT secret 解耦。
2. **二期管理接口**：按上表补充 users / chats / bindings / stats 四组管理 API。
3. **无需 CORS**：走服务端代理后浏览器不直连 Go 服务。

```
src/app/admin/

├─ teyvat-guide/
│  ├─ ServiceStatusPanel.tsx       # 服务状态（M1 已实现）

src/lib/teyvat/                    # 直连层：db.ts / entities/ / assets.ts
```

## 6. 响应体归一化

teyvatGuide 统一响应 `{ code, message, data }`（`code === 0` 成功），与本系统现有 `success/message` 风格不同，由网关层完成转换：

| teyvatGuide | 网关输出 |
| --- | --- |
| code = 0 | `{ success: true, data }` |
| code = 400 | `{ success: false, message: "参数错误" }` |
| code = 404 | `{ success: false, message: "资源不存在" }` |
| code = 502 / 503 | `{ success: false, message: "上游服务异常，请稍后重试" }` |
| 网络不可达 | `{ success: false, message: "teyvatGuide 服务不可达" }` |

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| Go 侧 `AutoMigrate` 改表结构，影子实体漂移 | 影子实体只映射稳定字段；表结构变更属 teyvatGuide 大版本事件，同步更新影子实体 |
| 主键冲突/误删映射 | 删除走确认弹窗；upsert 语义明确「按 ID 覆盖」 |
| reload 时 Go 服务不在线 | 写库不阻塞，页面提示手动 reload；服务状态面板可查在线状态 |
| 数据库账号权限 | 本系统需要 teyvat_guide 库读写权限；凭证只存服务端 env |
